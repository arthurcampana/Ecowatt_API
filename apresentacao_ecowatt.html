Evolução

Evolução do frontend

O frontend foi migrado de páginas estáticas (HTML/CSS/JS puro) para uma Single Page Application em React + Vite, com um sistema de design próprio.

Antes — HTML/JS puro

  • Páginas .html separadas, Bootstrap
  • Servido via Live Server
  • Sem reaproveitamento de componentes
  • Tema único (claro)

Depois — React + Vite (SPA)

  • Componentes reutilizáveis e rotas (React Router)
  • Tema claro/escuro persistente
  • Sidebar retrátil, ícones SVG, layout coeso
  • Toasts, modais, empty states e skeletons

A API REST (Spring Boot) permaneceu a mesma — a migração foi apenas na camada de apresentação, consumindo os mesmos endpoints.

Testes

O que falhou e os aprendizados

Defeito 1 — Alteração de usuário

Ao alterar o nome, o sistema gravava o nome no lugar da senha. Corrigido: a senha só muda se uma nova for informada.

Defeito 2 — Cálculo de consumo

Ao mudar só as horas, o consumo não recalculava. Corrigido: recálculo quando horas ou equipamento mudam.

Defeito em aberto (IDOR): com token válido, um usuário conseguia acessar dados de outro informando o ID. Identificado por análise de segurança; plano de correção: validar, em cada operação, se o ID solicitado pertence ao usuário do token, com teste de regressão.

Aprendizado: os testes viraram especificação. Cada defeito corrigido deixou um teste de regressão que trava o erro se ele voltar.

Dados

Big Data: foco em comportamento

Hoje não usamos Big Data — o volume atual (consumos inseridos manualmente) é tratado tranquilamente pelo PostgreSQL. Se a base de usuários crescer, o valor do Big Data não estaria em sensores, e sim em entender o comportamento de consumo das pessoas.

BLOCO 3

Modelo de Negócio

Qual dor resolvemos e como o negócio funciona.

Negócio

Proposta de valor e impacto

A dor

O consumidor só vê o total da fatura em kWh. Não sabe qual aparelho pesa na conta nem como uma compra vai afetar o gasto.

O benefício

Visibilidade clara e simulação do consumo, transformando dados técnicos em decisões do dia a dia.

Impacto que gera valor

  • Economia: identificar desperdícios e reduzir a conta
  • Previsibilidade: simular antes de comprar um aparelho
  • Consciência: metas e alertas de consumo
  • Sustentabilidade: uso responsável de energia (Agenda 2030)
Negócio

Estrutura do modelo e público-alvo

Modelo

SaaS (software como serviço), acesso web por assinatura, sem instalação.

Freemium B2C

Plano gratuito básico para residências; plano pago com relatórios e previsões.

B2B

Plano para pequenas empresas: múltiplos pontos e relatórios gerenciais.

Público-alvo

Residências

Famílias que querem controlar e reduzir a conta de luz.

Pequenas empresas

Comércios e escritórios que precisam acompanhar o custo de energia.

Modelo de negócio proposto a partir do produto. O documento acadêmico (Canvas) foca em entregas e stakeholders; a monetização aqui é uma proposta de evolução comercial.

Go-to-Market

Estratégia de vendas
